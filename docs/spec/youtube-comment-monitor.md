# YouTube 指定视频新增评论监控

## 已确认需求
官方 YouTube Data API；指定视频的公开顶层评论；北京时间每天 07:00–22:00（含 22 点）每小时整点检查；推送飞书；每个新监控目标首次运行只建立基线，不推送历史评论。API Key 已配置；视频为 7sVn00ECFBw、O31JLO208nQ、4jRS1RN0BjE；用户要求新建专用飞书群。

## 方案与边界
用户选择官方 API，不采用第三方采集或浏览器抓取。复用现有 TypeScript、SQLite 和飞书机器人凭据；新增独立模块，不改现有会话控制逻辑。无自动回复、AI 分析、楼中楼、UI。

实现约定：
- 环境变量显式开启，视频 ID/链接与唯一 chat_id 必填；缺配置不发送，也不猜群。
- 首次成功读取最新一页，保存初始时间界线与已见 ID；不需要下载全部历史。请求失败不完成基线。每个视频/群组合单独建基线。
- 后续 order=time 分页，回看上次完整扫描之前 24 小时（但不早于初始基线）。只通知基线之后发布且未见的顶层评论；编辑不算新增。
- 使用扫描开始时间作为成功水位，只有分页完整成功才推进；单轮每视频最多 100 页，超限报错且不推进，不将截断结果当完整。
- SQLite 事务保存评论去重键与待发送记录；飞书成功后标记，失败指数退避重试，每分钟独立投递待发，每目标每分钟最多 100 条；固定 uuid 减少不确定响应导致的重复，但不宣称跨服务 exactly-once。
- 原文采用飞书 post 的 text 标签，不解析 Markdown、@ 或指令；只保存必要原文，发送成功即清除本地原文，过期待发送内容在 29 天后删除并记日志。
- 默认每 60 秒检查持久化到期时间，每目标按 Asia/Shanghai 的 07:00–22:00 整点采集；启动将旧半小时到期时间向上对齐至合法整点，只在允许时段执行已到期目标。单进程不重叠，数据库租约保护多进程，停止等待在途任务。
- API 网络请求有超时；错误只记安全类别，不记录 Key、token、响应全文或评论原文。

## 限制
24 小时回看无法保证发现被长时间隐藏后才公开、但发布时间很早的评论。每页请求不是一致性快照，重叠回看缓解分页变化但不能保证 YouTube 上所有短暂可见评论。首次基线时之前发布的评论永不通知。超过 100 页的积压不推进水位，需运维调整频率/范围。飞书已经发出的原文是外部副本，启用前须确认其保留/删除策略。

## 验收
首次静默、空视频基线、后续仅新增、跨页扫描、旧评论编辑不推送、重启不重复、失败不丢待发、单视频失败不影响其他目标、禁用不调用网络、错误不泄密、停止与租约保护、配置校验；全套 tests/check/build。

## API 调用统计与额度提醒（2026-11-07）
用户要求统计调用量并在70%/90%提醒专用群。按官方默认每日10,000单位（可配置）和America/Los_Angeles配额日计数，自动处理夏令时，不使用北京时间零点。仅统计本监控实际发起的YouTube请求尝试，当前3种list接口每次1单位，成功/错误/分页均计数，网络未到达服务端可能保守多计。飞书与本地轮询不计。启用前调用不回填、其他程序消耗不可见，所有提醒必须标明本地估算而非项目真实总量。

计数和阈值提醒入队同一SQLite事务，按project/day/chat/threshold唯一去重，重启保留。每次达标各提醒一次，发送失败指数退避重试，不标记成功；跨配额日丢弃过期未发送提醒并审计，避免旧警报冒充新日。提醒包含触发比例、估算单位/额度、配额日、北京时间重置时间、统计启用时间及范围限制。不自动停用监控，不扩大Google权限，不用额外Google查询来统计。

复用现有租约内串行发送，在每轮开始、频道发现后、视频采集后处理待发告警，失败不能阻塞正常评论监控；长分页最多延迟一个视频/频道扫描结束。使用固定uuid减少不确定响应重复，仍不宣称跨系统exactly-once。增加只读统计命令查看接口分项和提醒状态，不改基线。
